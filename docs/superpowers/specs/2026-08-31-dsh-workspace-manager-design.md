# DeepSeek Harness 工作区管理插件设计

> 历史设计文档：其中自建缓存目录与内容分类方案已由 `1.1.0` 的 DSH 原生目录方案取代。当前行为以仓库根目录 `README.md`、验收文档和代码为准；此文件仅保留设计演进记录。

## 1. 目标与范围

本插件是随 DeepSeek Harness（DSH）启动的 Windows 全局 Cordis 插件，不是 Codex 插件，也不修改 DSH 官方源码。它在 DSH 原生设置系统中提供“工作区管理”入口，补齐已归档对话管理、对话专属缓存清理、重要产出防误删、本地备份和版本更新提示。

首个公开版本只支持 Windows。不接入云盘账号，不静默自更新，不引入数据库或新 UI 框架，不展示普通对话，也不重复提供平台已有的主动归档入口。

## 2. 总体架构

### 2.1 DSH 适配层

- DSH 原生 `archivedSessionIds` 是归档状态的唯一真实来源。
- 页面打开、用户刷新和收到归档状态事件时，重新校验平台状态。
- 恢复后必须重新读取原生归档集合，只有 ID 已移除才报告成功。
- 优先调用 DSH 未来公开的取消归档 API。对当前 `0.1.1-rc.2` 使用集中在单一文件中的兼容适配，通过 workspace domain 的持久化状态删除归档 ID，依赖 DSH 自有 `domain/changed` 事件同步界面。
- 启动时检测 DSH 版本和所需服务。不匹配时禁用写操作并显示兼容错误，不猜测内部结构。

### 2.2 全局文件登记层

插件监听整个 DSH 的会话创建、标题、事件和结束事件，登记每条对话的创建时间、工作目录、项目归属、专属缓存路径、标题和最终产出。这些是文件映射数据，不得用来伪造平台归档状态。

删除范围仅限插件已登记、且位于允许根目录内的对话专属缓存。用户原有项目源码目录永不自动删除。

## 3. 缓存目录与分类

### 3.1 项目对话

```text
<项目根目录>/
  .cache/
    <对话短标识>/
      会话记录/
      文档/ 表格/ 演示/ 代码/ 脚本/ 配置/ 数据/
      图片/ 音视频/ 压缩包/ 日志/ 其他/
```

项目内每条对话必须使用独立子目录，保证删除单条对话时不会影响同项目其他对话。

### 3.2 日常零散对话

```text
<DSH 主工作区>/
  daily_conversation/
    YYYY-MM-DD/
      <关键词-创建时间-短标识>/
        会话记录/
        文档/ 表格/ 演示/ 代码/ 脚本/ 配置/ 数据/
        图片/ 音视频/ 压缩包/ 日志/ 其他/
```

关键词复用 DSH 已生成的会话标题，不为目录命名另外调用模型。当某日最后一条对话缓存被删除后，自动删除已变空的日期目录。

## 4. 已归档对话管理

- 列表只展示 DSH 原生已归档对话。
- 支持搜索、多选、单项或批量恢复、单项或批量移入回收站。
- 批量操作逐项执行，单项失败不阻断后续项，最后返回成功和失败汇总。
- 页面不提供普通对话列表或主动归档按钮。

## 5. 自动重要文件保全与安全删除

用户触发“移入回收站”后，系统自动执行：

1. 根据对话登记数据确定专属缓存边界。
2. 本地规则排除依赖、日志、临时文件、编译产物和明显可重建缓存。
3. 调用 DSH 当前默认模型读取候选文件实际内容。文本、代码和结构化数据按限额读取；大文件抽取代表性片段；支持的图片通过模型图像能力审核。
4. 模型按“最终成果、无法轻易重建、具有用户内容”三项标准返回结构化保留决定和理由。
5. 自动将建议保留的文件复制到 DSH 主工作区的全局“保留文件”目录，不再要求用户逐项确认。
6. 以 SHA-256 去重，记录来源对话、来源项目、原始路径、保存时间和 AI 理由。
7. 完整校验保留副本的大小和哈希。任一应保留文件复制或校验失败时，中止该对话的删除。
8. 将 DSH 会话数据和已登记的对话专属缓存移入 Windows 系统回收站。
9. 删除空的对话父目录或日期目录，更新映射和操作日志。

AI 调用失败时不献祭安全性：默认中止删除并告知用户，不自动降级为“全部不保留”。

## 6. 保留文件与提醒

- 保留文件库对整个 DSH 生效，不隶属于某个项目。
- 支持查看来源、打开所在位置、恢复至原位置或用户选择的目录，以及单独移入回收站。
- 原路径已被其他文件占用时不覆盖，要求用户选择新位置。
- 用户可设置检查周期。提醒只在 DSH 应用内显示，不发送 Windows 系统通知。
- 页面明确提示：保留文件是防误删区，不是外部云备份。

## 7. 本地备份

- 手动备份支持保留文件库、单条对话缓存和单个项目的插件缓存。
- 备份目标是用户选择的本地或网络磁盘目录，插件不认证云盘账号。
- 自动备份周期按天配置，下次执行时间持久化，DSH 停止期间错过的备份在下次启动时补执行一次。
- 生成带时间戳的 ZIP，完成后测试压缩包可读并核对清单。
- 默认保留最近 5 个版本，数量可配置；超出数量的旧备份移入回收站。
- 提供备份清单和恢复入口。恢复不默认覆盖现有文件。

## 8. DSH 原生设置 UI

客户端通过 DSH `settings.section` 插槽在左侧添加“工作区管理”，与通用设置、模型、插件和 Agent 预设同级。点击后仅切换右侧内容，不创建独立页面。

页面使用 DSH 原生字体、颜色、间距、分隔线、圆角、按钮和明暗主题，不引入新 UI 依赖。视觉原则是高级、简约、信息密度适中。

页面包含四个功能区：

1. **已归档对话**：搜索、多选、恢复和移入回收站。
2. **保留文件**：文件列表、来源、恢复、删除和提醒周期。
3. **本地备份**：备份目录、手动备份、自动周期、保留数量和恢复。
4. **插件设置**：DSH 主工作区、缓存目录名称、AI 保全开关与内容限额、自动检查更新、兼容状态和诊断导出。

管理列表默认最多显示 5 行，超出后在区域内滚动，不分页。搜索和批量工具只在对应列表显示。危险操作使用 DSH 风格确认框和单一危险色。

## 9. 数据与迁移

状态保存在 DSH storage 目录：

- `config.json`：工作区、备份、提醒、AI 内容限额和更新设置。
- `state.json`：对话与专属缓存映射。
- `retained-files.json`：哈希、文件位置和来源索引。
- `operations.jsonl`：归档、恢复、删除、保全和备份的可追溯记录。

结构化文件包含 `schemaVersion`。升级时先备份旧数据，再原子写入迁移结果；失败时保留旧文件并禁用写操作。

## 10. 安全与错误恢复

- 客户端写操作使用 POST，并验证运行时会话令牌。
- 不存在通用的“删除任意路径”接口。客户端只传对话或保留文件 ID，服务端从已校验映射解析目标。
- 所有删除目标都须通过规范化路径和允许根目录边界检查。
- 复制文件和写入 JSON 使用临时目标加原子替换。
- 每个多阶段操作在 `operations.jsonl` 记录阶段。启动时检测未完成操作，已校验副本可继续，尚未删除的原文件保持不动。
- 日志导出默认脱敏用户名、密钥、文件内容和完整绝对路径。

## 11. 发布与更新

- host 和 client 使用同一语义版本，发布包包含版本、支持的 DSH 版本、文件哈希和变更说明。
- 通过 GitHub Releases 发布 Windows 一键安装包。安装器自动定位 DSH，备份原版本，安装 host/client，更新 DSH profile 并执行健康检查。
- 插件只检查新版本并提示用户。不在 DSH 运行期间静默替换文件。
- 更新保留用户配置、映射、保留文件和备份。卸载默认也保留用户数据，只有显式选择时才清除。

## 12. 测试与验收

### 自动测试

- 目录命名、分类、路径边界、哈希去重、原子状态与迁移。
- DSH 原生归档列表、归档事件、单项和批量恢复。
- AI 输入限额、结构化输出解析、模型失败时中止删除。
- 保留文件复制、哈希校验、恢复冲突和回收站操作。
- 备份生成、完整性校验、保留数量、错过任务补执行和恢复不覆盖。
- HTTP 方法、令牌、输入校验、路径越界与任意路径删除回归测试。
- 从任意安装路径运行 Loader 集成测试，测试不包含用户名或固定绝对路径。

### 真实 DSH 验收

1. 重启 DSH 后左侧设置出现“工作区管理”。
2. 平台归档对话后，管理列表无需重启即可显示。
3. 恢复后对话返回平台普通列表，且插件重新读取状态确认恢复。
4. 删除后重要文件已校验保存，对话与专属缓存可在 Windows 回收站找到，用户原项目不受影响。
5. 同日最后一条日常对话删除后，空日期目录消失。
6. 备份、提醒、更新检查、诊断导出和配置迁移在 DSH 重启后仍保持正确。

## 13. 实施边界

优先修复根因和完成真实闭环，不为未来平台或云服务预先建抽象。首版允许一个 DSH 兼容适配、一个 Windows 回收站实现和 JSON 文件状态。当 DSH 公开取消归档 API 或需要支持第二个操作系统时，再扩展对应边界。
