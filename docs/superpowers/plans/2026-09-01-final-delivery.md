# DSH 工作区管理最终交付计划

**目标：** 在 DeepSeek Harness 0.1.1-rc.2 的公开能力边界内，交付不会把“删除”误当成“取消归档”的 Windows 插件，并补齐保留文件、自动备份、精简 UI、安装与回归验证。

## 已批准的实现边界

- DSH 原生 `archivedSessionIds` 始终是归档状态唯一来源。
- 当前 DSH 没有公开的会话删除 API；删除采用持久化删除队列：首次点击后立即从插件列表隐藏并完成保留审核，下一次 DSH 干净启动时回收受管缓存和对应会话日志，再清除原生归档标记。
- 不调用 DSH 私有方法，不删除用户原始项目目录，不把删除失败伪装成成功。
- 重要文件由本地规则初筛、AI 内容审核并自动复制到全局保留文件库；任何审核或复制失败都阻止删除。
- 保留文件操作串行化，并允许按明确来源恢复。
- 自动备份提供关闭、按天周期、退出前尽力备份三种模式；显示上次结果与下次时间，拒绝递归/重叠备份目录。
- UI 保持 DSH 原生设置风格，正文只保留必要说明，高级选项默认折叠。
- 仅使用 Node、DSH、React 和 PowerShell 已有能力，不新增运行时依赖。

## 验证门禁

1. 先增加会失败的回归测试，再实现每项修复。
2. Host 单元、DSH 集成、Client 契约、安装器与发布包验证全部通过。
3. 使用临时 `DSH_HOME` 验证删除排队、重启收敛、保留文件、备份与失败回滚。
4. 构建新版本 ZIP，安装到用户 DSH；不使用真实对话做破坏性测试。
